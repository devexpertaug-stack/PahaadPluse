# Immersive mountain/forest landing + sitewide glassmorphism restyle (v1)

A three-feature frontend task: additive `--pp-*` mountain/forest palette tokens and `.glass-panel` utilities across the three theme-source files (FEAT-001), a single self-contained immersive landing HTML wired in as the ungated `/` homepage with the Metrics Overview relocated to `/dashboard` (FEAT-002), and a glassmorphism + interactive-3D restyle flowing through the shared UI primitives and layout shell into the 16 dashboard pages (FEAT-003). The approach is deliberately conservative: the restyle touches only primitives and the shell, so no dashboard page module is edited and the live-data wiring is carried along untouched. All four gates (frontend lint/vitest/build, backend ruff/pytest) are green and the landing's JS passes `node --check`.

Watch for: the landing's canvas/video/3D runtime behaviour cannot be verified in this sandbox (no browser, dev servers blocked) — only static spec conformance and build/lint were checked (confirmed, by environment). The landing is served inside a Next iframe but is otherwise an orphan: no server-rendered fallback and no non-JS entry into the product, so a user who blocks the remote mixkit/pexels media or disables JS sees a dead page with no path to `/login` (likely). The sole product entry affordances ("Book Now" button and the "Stays" nav link) both route to `/login`; the other two nav links are inert in-page anchors (confirmed).

**Verdict**: APPROVED

## High-level view

Token foundation is additive and consistent. The seven `--pp-*` hexes appear identically in `globals.css` (`:root` vars), `tailwind.config.ts` (`pp` color group), and `lib/theme.ts` (`palette.pp`), with the pre-existing alpine `--color-*` scales left intact, so existing rendered classes don't shift and the Badge/StatTile assertions survive.

Routing was restructured cleanly. `/` is now the ungated landing (an iframe over `public/pahaadpulse.html`), the overview page was `git mv`'d from `/` to `/dashboard` with its one internal filter string updated, and every consumer of the old `/` home — navItems, LoginForm redirect (plus its test), Sidebar brand link, and the Sidebar/Header active-route special-cases — was updated to `/dashboard` in lockstep. All 16 subsystem routes remain under the SessionGate-gated `(dashboard)` group and build cleanly.

The landing HTML conforms to the spec at the level that can be checked statically: single file, zero external libs, the seven exact asset URLs, the inline SVG data-URI logo, the exact DOM ids/classes, the pinecrest/earth/venus data model with the exact fact strings, and the full set of numeric constants (tilt `*37.4` / `*-33`, smoothing `*.009` clamped at 40ms, focal 850, radius 90, ~44-point rounded rect, 1100ms expansion, 1.3x transition rate, preloader `max(.25, duration/3)`, cursor lerp 0.2). Its runtime appearance depends on remote CORS media and canvas/rAF that only exist in a real browser.

The glassmorphism restyle is confined to the six UI primitives, the three shell components, and the login page. Because the 16 dashboard pages compose those primitives, the new look flows in without editing any page module, which is why `useLiveData`/`LoadState`/`liveBadgeProps` on all 17 page modules are provably untouched. The 3D tilt lives on an inner element and is disabled under `prefers-reduced-motion`.

Glass surfaces lean on `backdrop-filter` for legibility. Panels use translucent backgrounds (down to `bg-mist-white/60`) that rely on the blur actually compositing; where `backdrop-filter` is unsupported or disabled the content sits over a weaker wash than intended, though text colors stay dark on light so it degrades to readable rather than broken.

### Token foundation across the three theme-source files

The seven mountain/forest hexes (`forest #1b3b2a`, `moss #4e7a3f`, `leaf #7fb069`, `mist #cfe3d4`, `slate #243b35`, `stone #0c1410`, `amber #e5b25d`) are defined identically in `globals.css` `:root`, `tailwind.config.ts` `theme.extend.colors.pp`, and `lib/theme.ts` `palette.pp` (confirmed by reading all three diffs). `tailwind.config.ts` additionally gains a `glass` boxShadow and a `glass-sheen` backgroundImage; `globals.css` gains `.glass-panel`, `.glass-panel--dark`, `.glass-lift`/`.glass-lift-inner`, and `.pp-scenery`, plus a `prefers-reduced-motion` block that zeroes the lift transform. All additions are purely additive — the alpine `--color-*` tokens and `forest/mist/pine/dawn/sky/slate/alert` scales are untouched, which is why the StatTile `text-forest-800` and deep-pages/sentinel assertions still pass unchanged.

### Routing restructure: landing at `/`, product home at `/dashboard`

The overview page moved via rename (git reports `similarity index 99%`, a one-line change to its internal `navItems.filter((item) => item.href !== "/dashboard")`), so no overview logic was rewritten. Every reference to the old `/` home was updated together: `navItems` Overview `href`, `LoginForm` `router.push("/dashboard")` (with the test assertion updated to match, coverage preserved), the `Sidebar` brand `Link`, and the active-route special-cases in both `Sidebar` and `Header` (`item.href === "/dashboard" ? pathname === "/dashboard" : pathname.startsWith(item.href)`). The build confirms `/`, `/login`, `/dashboard`, and all 16 subsystem routes are present; the `(dashboard)` group's SessionGate layout is unchanged so the gating is intact.

The `deep-pages.test.tsx` and `sentinel-destination-pages.test.tsx` mocks still return `usePathname() => "/"`, which is now a non-existent product route. This is harmless because those tests render page components directly, not Sidebar/Header, so the active-route logic that keys on `/dashboard` is never exercised there — the 24-test suite passes. Worth noting only so a future reader doesn't mistake the stale mock value for a bug.

### Landing spec conformance (static)

```
<!DOCTYPE html> present; single file; grep for <script src|<link stylesheet|cdn|unpkg|
jsdelivr|three|gsap|jquery  ->  zero matches
```

The seven asset URLs match the spec exactly (FOG_FOREST 10086, LAKE_FOREST 35452, SNOWY_PINE 3392, RANGE_FLYOVER 26101, TO_CEDARVALE 26570, TO_MISTFALL 51683, MISTFALL_STILL pexels 167699 w=1600); the only other URL is the `w3.org/2000/svg` namespace inside the inline data-URI logo. The three background `<video>` elements (mars/earth/venus) and all media carry `muted playsinline preload="auto" crossorigin="anonymous"` with no controls/autoplay. The data model keys `pinecrest`/`earth`/`venus` with next-numbers `[03]`/`[02]`/`[06]`, Mistfall terminal with the still image, and the exact fact strings are all present verbatim.

The numeric constants in the JS match the spec:

```
pointer tilt   targetY = (x/W - .5) * 37.4 ;  targetX = (y/H - .5) * -33
smoothing      rot += (target - rot) * Math.min(1, dt * .009) ;  dt clamped to 40ms
projection     focal 850
rounded rect   4 corners x 11 samples (s = 0..10)  ~= 44 points ;  radius 90
expansion      animateValue(1100ms) ;  easeInOutCubic everywhere
transition     playbackRate 1.3 ;  freeze final frame into #scene-canvas, commit, revealMask
preloader      playbackRate = Math.max(.25, duration/3) ;  finish() guarded + 7000ms safety
cursor         lerp 0.2 per frame via translate3d
drawShade      gradient .52H (rgba(6,16,10,0)) -> H (rgba(6,16,10,.88)) over bottom 48%
boot           pause/rewind backgrounds -> resizeCanvas -> render -> rAF(draw) -> rAF(cursorLoop) -> runPreloader
```

`finish()` is guarded by a `finished` flag and backed by a 7000ms safety timeout, and `travel()` guards on `busy`/terminal-`venus` with a full `.catch` reset path, so the state machine can't wedge if a remote video stalls. None of this proves the experience *renders* — the canvas pixel sampling, video playback, tilt feel, and "zero console errors" all require a real browser with the CORS media reachable, which this sandbox can't provide.

### Landing as an orphan: no fallback path into the product

`app/page.tsx` renders only a full-viewport `<iframe src="/pahaadpulse.html">` with no overlay link, and the HTML's sole entry affordances are the `click` handlers on "Book Now" and the "Stays" nav link, both calling `goToLogin()` which navigates `window.top`/`parent` to `/login`. If JS is disabled, or the remote mixkit/pexels media are blocked by a network/privacy layer (plausible for third-party video hosts), the visitor is stranded on `/` with no way to reach `/login` or the dashboard. The spec itself floats an "overlay 'Enter dashboard' link on the Next landing page" as an option precisely to avoid this; it wasn't taken. The other two nav links ("Explore" → `#explore`, "Retreats" → `#planets`) target ids that don't exist in the document, so they're inert.

### Restyle confined to primitives and shell; dashboards stay live

`git diff --name-only` over `app/(dashboard)/` shows only the relocated `dashboard/page.tsx` (the rename); no subsystem page module changed. All 17 page modules still reference `useLiveData` and `LoadState`/`liveBadgeProps` (grep count 17 each). Because `LoadState` renders through the restyled `Card`, the load/empty/error panels inherit the glass look without any per-page edit — the restyle genuinely flows from the primitives. `Card` and `StatTile` keep their title/subtitle/footer and label/value/hint markup, moving the 3D rotation onto a `.glass-lift-inner` child so layout is unaffected and the reduced-motion opt-out can neutralize it. `Badge`'s default `forest` tone still emits `text-forest-800`.

### Glass legibility depends on backdrop-filter compositing

The restyled surfaces use translucent backgrounds — `Card`/`StatTile` at `bg-mist-white/70`, `Table` at `/60`, the login card at `bg-mist-white/60`, the `Header` at `bg-mist-white/70` — layered over `.pp-scenery` and relying on `backdrop-filter: blur()` to build contrast. The author deliberately kept `.pp-scenery` light so dark forest text stays readable, and text colors remain dark-on-light, so on engines where `backdrop-filter` is unsupported or user-disabled the panels wash out but text should still be legible. Worth a visual check in that degraded mode since the opacity was tuned assuming the blur is present.
