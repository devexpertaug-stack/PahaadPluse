# Sample Mussoorie Review Dataset — Datasheet (Req 2.8)

This datasheet documents the checked-in sample review dataset used by the
PahadPulse Market Radar demo. It follows the "Datasheets for Datasets" spirit:
what the data is, where it came from, how it was collected and how reviewer
identities are protected.

The dataset lives at `data/sample_reviews/mussoorie_reviews.json` and is
**generated from code** (`backend/app/seed/sample_reviews.py` via
`backend/scripts/build_dataset.py`). Because the records and this datasheet are
produced from the same source of truth, the record counts below are guaranteed
to match the actual dataset (an automated test asserts this).

## 1. Motivation

The dataset provides a realistic, multilingual review corpus for a Cluster of
Mussoorie (Uttarakhand) hospitality Properties so the Market Radar pipeline —
parsing, normalisation, language detection, Hinglish transliteration, aspect
normalisation and aspect-level sentiment — can be exercised end to end offline,
with no live platform access or third-party credentials.

The cluster's **Home_Property is The Forest Season Resort**
(`mus-forestseason`), a Mussoorie resort set in the deodar forest. It carries a
deep, **~18-month** multi-platform review history (dated roughly January 2023 to
June 2024) so the Deep analytics — time-series decomposition, Bayesian
changepoint detection, Time Machine, Playbook and gap-finder — have real depth
to work with. The six surrounding properties (Pine View Inn, Deodar Residency,
Cloud Valley Resort, Himalayan Nook Homestay, Mall Road Heritage Lodge and
Camel's Back Retreat) are competitors that provide the cluster context.

Every property has at least one review on each of the five platforms, and the
corpus mixes English (`en`), Devanagari Hindi (`hi`) and romanised Hindi
(`hi-Latn`). The Home_Property (The Forest Season Resort) carries the bulk of
the records — a deterministic, seed-reproducible set generated across all five
platforms and spread over the ~18-month window — while the competitors keep one
compact review per platform. A number of records intentionally omit the public
source URL so the website's "source URL unavailable" handling (Req 2.9) can be
demonstrated.

The Home_Property's reviews are **generated** by a pure, seeded generator
(`backend/app/seed/forest_season_reviews.py`, seed `20240915`), then fed through
the **real** ingestion pipeline (`ReviewParser` + `enrich`) exactly like
collected reviews. The same JSON file can also be posted through
`POST /market-radar/collection/upload` to exercise the live Review_Collector
path end to end. Because the generator is deterministic, the same seed always
yields identical records and the counts above stay stable.

## 4. Collection method per platform

> **Honesty note.** This project is built and verified in a sandbox that cannot
> (and must not) crawl the live review platforms: there is no free,
> credential-less path to do so, and bulk scraping would breach each platform's
> terms of service. **Live collection from Google, MakeMyTrip, Booking.com,
> TripAdvisor and Agoda requires each platform's official API or written
> permission** (and is gated in code behind robots.txt + terms checks, Req 2).
> The records here are therefore a **synthetic, representative dataset** — the
> Home_Property's reviews are *generated* by a seeded generator and the
> competitors' reviews are hand-authored — written to mirror the structure,
> typical length, rating distribution and language mix (English / Devanagari /
> Hinglish) of genuine public Mussoorie reviews. The dataset is clearly labelled
> as representative/synthetic and is **not** presented as a verbatim scrape. It
> is run through the identical parse → language → sentiment/aspect → normalise →
> market-model pipeline that real collected reviews would use.

For each platform the intended/real-world collection method is:

| Platform | Intended collection method | Terms considerations |
| --- | --- | --- |
| Google | Official Places/Maps review surfaces or manual review of public listings | Respect Google Maps Platform terms; no bulk scraping of protected endpoints |
| MakeMyTrip | Public property review pages | Respect robots.txt and site terms; rate-limited, identified crawler |
| Booking.com | Public property review pages | Respect robots.txt and site terms; native 1–10 rating scale |
| TripAdvisor | Public property review pages | Respect robots.txt and site terms; sub-category ratings used for aspects |
| Agoda | Public property review pages | Respect robots.txt and site terms; native 1–10 rating scale |

Where non-official (crawl-based) collection is used, the responsible-collection
controls in `app/services/market_radar/responsible.py` apply: robots.txt is
fetched and cached for 24h, disallowed URLs are skipped and counted, a
server-error/timeout disables the whole domain, requests are rate-limited to at
most 1 request / 5s per domain (or the published crawl-delay if longer), and a
`PahadPulse/<version> (+mailto:<contact>)` user-agent is sent on every request.

## 5. Source URLs

Each record retains a public `source_url` (Req 2.1). Because specific review
permalinks are not fabricated in this sandbox, the stored URLs are **honest
placeholders** that follow each platform's property-page URL pattern (e.g.
`https://www.booking.com/hotel/in/<slug>-mussoorie.html`) rather than invented
per-review permalinks. Records that omit a URL set `missing_source_url=true` and
are surfaced on the website as "source URL unavailable".

## 6. Pseudonymisation method (Req 2.6, 2.7)

Reviewer display names are **never stored or logged**. Each stored record carries
only an `author_pseudonym`, computed as a salted HMAC-SHA256 of
`"<platform>\x1f<lower-cased display name>"`, prefixed with `anon-` and
truncated. The salt is read from the `PSEUDONYM_SALT` environment variable /
secrets store and is **never committed** to the repository or written into the
dataset. The pseudonym is stable per `(reviewer, platform)` across collection
jobs, so the same reviewer maps to the same token on repeat runs, while the raw
identity cannot be recovered from the dataset.

## 7. Licence / terms considerations

The representative text in this dataset is authored for this project and is
released under the repository's licence for demonstration and testing. In a real
deployment, collected review text remains subject to each source platform's
terms of service and applicable copyright/database rights; only pseudonymised,
aggregate-friendly records within those terms should be redistributed.
